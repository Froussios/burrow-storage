# Decisions

Architecture decision records, shortest useful form. A decision is binding for implementers until a
new entry supersedes it. D1–D8 originate in `docs/design-review.md` §5 and change a MUST in the
requirements; they are adopted by default and tracked for owner confirmation in the "Confirm
design-review decisions" issue. D9 onwards are implementation choices that the requirements leave open.

| # | Decision | Status | Rationale (short) | Consequences |
|---|---|---|---|---|
| D1 | Reference Firestore adapter uses the **REST API via `fetch`**, not the Firebase JS SDK | adopted, awaiting owner confirmation | SDK ≈ 100 KB gz vs 12 KB budget; REST gives `keepalive` for unload flushes; no `initializeApp` collision; rules apply identically | No `subscribe` in v1 → adaptive polling (architecture §7.4). An SDK adapter with `onSnapshot` is a follow-up issue |
| D2 | One `items` store with compound key `[app, key]` instead of one object store per app | adopted, awaiting confirmation | Avoids IndexedDB `versionchange` upgrades on first use of each new app, which block while other tabs hold the DB | Per-app clear is a key-range delete |
| D3 | `put` is a **blind write arbitrated by rules**; read only to classify a 403 | adopted, awaiting confirmation | Halves happy-path cost; rules evaluation on a single-document write is atomic in Firestore, so BE-1 holds | Conformance suite includes a 10-writer race test on the emulator |
| D4 | **No passphrase provider in v1**; sync codes carry random secrets only (version byte `0x01`) | adopted, awaiting confirmation | Decided default in the requirements; PBKDF2 in core is dead weight | ENC-3 stays as the rule a custom provider must follow; version byte `0x02` reserved |
| D5 | Device wrapping uses **AES-GCM under a non-extractable key**, not AES-KW | adopted, awaiting confirmation | AES-KW wraps `CryptoKey`s; the raw secret would have to pose as an HMAC key to round-trip | Same security, straight code path |
| D6 | Events are a chrome-style **`BurrowEvent<T>`** (`addListener`/`removeListener`/`hasListener`), not `EventTarget` | adopted, awaiting confirmation | `EventTarget` is not generic and dispatches `Event` objects; `chrome.storage` ports expect the listener shape | Tiny emitter in `util/events.ts` |
| D7 | **No URL-fragment transport** for the sync code in v1 | adopted, awaiting confirmation | Secret would land in browser history (SEC-1) | QR codes carry the plain code; the page passes it to `link({ code })` |
| D8 | API additions: `linked`, error codes `not-linked` and `unsupported`, config `compress` and `debug`, `backend: null` = local-only, `rememberDevice: false` starts **unlinked** | adopted, awaiting confirmation | Closes design-review Q1 (orphan vaults), SYNC-4, T2, NF-3 | See architecture §3 |
| D9 | Repo layout: **single package**, two entry points (`.` and `./firestore`), IIFE bundle includes both | adopted | Simplest publish; the Firestore REST adapter is small enough that a separate package buys nothing | Size budgets per entry in CI |
| D10 | Tooling: **TypeScript 5 strict, tsup for builds, vitest + fake-indexeddb for unit tests, fast-check for properties, Playwright for browser tests, firebase-tools emulator + `@firebase/rules-unit-testing` for rules, size-limit, eslint + prettier, npm, Node 20+, GitHub Actions** | adopted | Mainstream, zero-config-ish, all runnable headless in CI | Documented in CLAUDE.md |
| D11 | Test vectors are generated by an **independent Python script** (`hashlib`, `hmac`, `cryptography`) and committed | adopted | A TS implementation checked against vectors it generated itself proves nothing | `scripts/gen-vectors.py`; vectors in `test/vectors/` |
| D12 | **Leader tab** does all network I/O; election via `navigator.locks`, heartbeat fallback on a `localStorage` sentinel holding a timestamp | adopted | Only one tab syncing avoids self-conflicts on the manifest | Followers get remote changes via `BroadcastChannel` |
| D13 | Equal-`ts` tie-break: **tombstone beats value**, then bytewise-greater JSON | adopted | Deletes idempotent, deterministic convergence | Property-tested |
| D14 | Clock: `now() = max(Date.now(), maxRemoteTs + 1, lastLocalTs + 1)` | adopted | Monotonic per device; a local write always sorts after everything the device has seen (SYNC-11) | A fast remote clock can push local `ts` ahead of wall time; harmless |
| D15 | Facade `getItem` returns strings as-is and **`JSON.stringify`** for non-string area values | adopted | Deterministic, lossless for round-trips through `set` | Documented in README migration recipe |
| D16 | Push on unload: **keepalive only for envelopes ≤ 32 KB**; larger items wait for the next load | adopted | `fetch` keepalive body budget is 64 KB per page | Documented under Offline |
| D17 | `exportCode()` keeps **one raw copy** of the root secret in a closure for its lifetime; everything else is a non-extractable `CryptoKey` | adopted | `exportCode()` and `protect()` need bytes; two representations would be more surface, not less | SEC-1/SEC-2 satisfied for every derived key |
| D18 | Versioning: vault format `v`, derivation salt and sync-code version byte are **public contract**; changing any of them is a major version with a migration | adopted | From the NF table | `v: 1` everywhere in v0.x and 1.x |
